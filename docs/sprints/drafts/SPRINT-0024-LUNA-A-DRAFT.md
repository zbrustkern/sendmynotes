# SPRINT-0024 — Complete personal account (Luna planning lane A)

## Pyramid Index

- **L0:** Turn the signed-in account into a private home for sent cards, saved fronts and uploads, people and occasions, reminders, settings, and resumable drafts.
- **L1:** Reuse existing orders, Firebase identity, invited Upload studio, media pipeline, draft store, and transactional email infrastructure. Freeze server-owned contracts first; preserve guest checkout and immutable paid orders.
- **L2:** Deliver all six account destinations and history/library/contact/date/builder handoffs, then prove ownership, snapshots, calendar rules, opt-in, and duplicate-safe reminders with synthetic data and fake transports.

## Complete user flows

1. **Overview/history:** signed-in menu → account overview → bounded card history → read-only detail with the historical cover, message, handwriting choice, and recipient/return address captured for that order. “Send again” seeds a new draft from a snapshot; it never mutates or resubmits the paid order. Preserve secure guest order access; never put guest bearer capabilities in account URLs.
2. **People/dates:** create or edit a person with optional postal address, relationship, private note, and multiple occasions; choose person/occasion in the existing address step; update the person only after explicit sender consent. Imports are reviewable, conservatively deduplicated, and report partial results. A person/date does not require a postal address.
3. **Images/Studio:** account → Saved images with Card fronts and Uploads → explicitly save a generated front or intentionally retain an uploaded source through the existing private Studio → reuse an immutable front rendition → existing accepted-design handoff → normal sender review before checkout. Do not create a second image processor or call a source upload a checkout-ready front. Preserve invited grants, TTL, quotas, and privacy unless separately authorized.
4. **Dates/reminders:** agenda → date editor with reminder opt-in initially off → concrete next reminder date/time in confirmed account zone → pause globally or per occasion → safe unsubscribe. Email goes to the sender, never recipient. Links seed a draft; no card is automatically sent.
5. **Drafts/settings:** save/resume owner-scoped drafts across devices; offer guest import explicitly with conflict recovery. Settings cover name, personal default return address, verified reminder destination, IANA timezone, global pause, export/deletion requests, and sign-out. Show retention before saving/expiry; 90 inactive days is proposed and needs a confirmed policy before release.

## Shared contracts to freeze before lane execution

Parent/coordinator owns shared contract files and integration. Freeze exact entity fields and route envelopes before parallel edits. Every endpoint derives UID from a verified Firebase identity token (or established secure server session); body/query UID is never authority. Reauthorize each linked contact, occasion, asset, order, and draft for that UID. Email-based order association requires verified email plus existing guest-order access rules. Do not use the whole-document POST to /api/account for new entities; it risks overwriting concurrent state. Preserve it as a compatibility/read facade while new APIs write per-record owner subcollections. Use bounded reads, schema validation, stable IDs, idempotency keys for creates/imports, version/expectedVersion for edits, and structured errors (unauthorized, forbidden, not_found, conflict, invalid, unavailable). Failures retain dirty input.

Suggested storage, subject to current wrappers and rules: users/{uid}/accountPreferences/current; contacts/{contactId}; occasions/{occasionId}; images/{imageId}; drafts/{draftId}; reminderOccurrences/{occurrenceKey}; and server-only reminderOutbox/{occurrenceKey}. Records carry owner UID server-side, stable ID, version and timestamps. Contacts permit no address. Occasions reference contact IDs. Persist explicit opt-in, consent timestamp/source, and leadDays=14. Never infer consent from an old default-true checkbox.

Migration is repeatable: map saved-address IDs to stable contacts; embedded occasion to a stable event; preserve saved return address; retain old records until checks pass. Legacy reminder import requires deterministic owner/contact/date matching and proven consent. Pause ambiguous or implicit opt-ins and explain the state. No migration email. Record a migration version/counts and make rollback possible. Do not let old full-array writes overwrite migrated/new per-record writes; version-guard or retire those callers first.

History reads existing orders and renders immutable order-bound fields/snapshot where present. If baseline lacks frozen artwork/note/style/address fields, add a snapshot atomically at creation for new orders and backward-compatible display from existing order fields for old orders. Never reconstruct history from current contacts. Paid/payment/refund/fulfillment state stays read-only. Do not expose payment secrets, guest bearer tokens, private upload URLs, raw card data, or provider capabilities in account payloads/logs.

Image entity stores owner, kind (generated_front, uploaded_source, upload_front), provenance/source ID, immutable rendition/master ID and hash, dimensions, saved/deleted timestamps, and reuse capability. Save references a server-created owned generation/design/asset after availability checks; never fetch a client URL. Do not extend source TTL implicitly: explicit save is quota/retention-aware and defines deletion/dependency behavior. Checkout resolves the same immutable rendition. Reuse does not rerun generation. Front geometry remains verified 17:22 and preview remains approximate.

Draft entity stores ID/version, immutable front reference, note/style, contact/occasion refs, recipient/return snapshots, progress, timestamps and expiresAt; no payment state, secrets, or order capability. Saves/imports are idempotent or versioned. Conflict offers reload and copy/recovery; failure retains local edits. Sign-in offers explicit guest import, never silent overwrite. Every reused draft still goes through ordinary sender review and payment.

Calendar rules use a shared pure module, not JavaScript date rollover. Validate real month/day. Birthday/anniversary default annual; Other can be annual or one-off, and one-off requires a year. Original year is display/milestone only. Use confirmed IANA timezone, schedule at 9 a.m. local time 14 calendar days before, and show date/time/zone. DST/year boundaries use calendar arithmetic. Feb 29 defaults to Feb 28 in non-leap years; editor may choose March 1. If event is under 14 days, offer separate opt-in for tomorrow; if today, agenda only/no stale job. Past one-off events do not send; annual events roll forward.

Outbox key is stable per owner + event + occurrence date + channel, including edit/revert. Event edit/delete/pause invalidates old versions. Claim with a transaction/lease to avoid concurrent dispatch; immediately before provider call recheck current event version, consent, account pause, verified address, future event, and linked paid-card suppression. Log attempts/provider IDs, use provider idempotency where supported, and reconcile uncertain acceptance rather than blindly resend. Provider acceptance means “Sent,” not delivered. Catch up once only within 48 hours while event is future; older rows become missed. A paid card explicitly linked to the occurrence suppresses its pending reminder; failed/canceled card restores eligibility only if same due rules allow. Names never link/suppress.

Unsubscribe GET is read-only for mail scanners. Minimal unauthenticated POST applies signed opaque single-purpose token to disable only occasion reminders and invalidate queued work; order updates remain separate. Destination change requires verification before reminders resume. Global pause preserves event choices. Existing /api/reminders identity path must not be used as account write security boundary; preserve legacy consumers via audited adapter only. New writes are authenticated owner routes.

Use local emulator/injected fake repository, synthetic browser fixtures, injected clock and fake mail transport. Never contact a live provider.

- **Auth/ownership:** absent/expired token → 401; foreign owner/linked entity denied without existence leak; body/query UID ignored; verified email required for legacy order association; bounded pagination; malformed/oversized data rejected; rules deny unauthorized client writes.

## Risks and mitigations

- Legacy whole-user writes can erase concurrent updates: per-record subcollections, migration versioning and guarded compatibility callers.
- Old reminder default may masquerade as consent: uncertain rows off, visible review state, no backfill mail.
- Provider timeout can duplicate mail: stable occurrence key, claim/lease, immediate consent/version recheck, idempotency and reconciliation tests.
- Account timezone/email may be unconfirmed: do not silently substitute browser timezone; reminder unavailable until confirmed destination and zone exist.
- Upload entitlement and TTL are delicate: keep invitations and quota; explicit owner-bound saved references; no vendor or grant change.
- Old orders may lack full snapshots: render their own persisted fields and freeze new snapshots going forward; never use mutable contact data.
- Large scope: complete every surface with honest unavailable states rather than defer whole features; identify actual backend blocker precisely.
- Copy risks overclaim: comply with canonical specs; no human-handwriting, exact physical preview, delivery guarantee, stock/finish, or conversion claims.
