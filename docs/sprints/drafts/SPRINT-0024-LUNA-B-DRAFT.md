# SPRINT-0024 Luna B planning draft — A complete personal account

## Pyramid Index

- **L0:** Turn the signed-in account into a useful, private personal collection: review accepted orders, reuse saved art, manage people and dates, choose whether to receive reminders, and resume durable drafts.
- **L1:** Ship connected mounted routes and builder handoffs against owner-scoped persistence; preserve guest sending, existing Upload Studio entitlements, immutable order records, and honest operational states.
- **L2:** Baseline gaps, shared contracts, three exclusive execution lanes, staged delivery gates, and safe validation below.

## Baseline audit and implications

The active app is Next.js App Router. `/new` mounts `app/preview/entry/client.tsx` and `components/flow/FlowHeader.tsx`; the legacy builder is still mounted from other routes. `FlowHeader` has a signed-in “My account” link and entitlement-gated `/create/upload`, but no direct Address book shortcut. Keep both active builder entry points working and add account navigation to the shared header used by `/new`; do not implement a second builder.

`app/account/page.tsx` is one large client page with history/address tabs, return-address editing, contact import, upcoming dates, and reminder toggles. The route's own history fetch omits the bearer token even though `/api/account` requires it; this can make an API failure look like an empty collection. `AuthContext` does send a bearer token, but its account writes replace/merge `savedAddresses` as a whole array. This is not suitable for concurrent contact/date CRUD. Move account screens onto an explicit authenticated data layer and distinguish loading, empty, partial, stale, forbidden, and retryable error states.

The account API (`app/api/account/route.ts`) stores embedded `savedAddresses`, one optional occasion per address, and legacy `savedCovers`. Existing reminder routes/storage/email helpers exist (`app/api/reminders/route.ts`, `lib/reminders.ts`, `lib/email-alerts.ts`), but no production scheduler/dispatcher was located in the inspected source. Existing account UI posts reminder writes during imports and has opt-in inconsistencies. Do not make that legacy endpoint the new occasion write path.

This checkout already contains the Upload Studio from SPRINT-0022: `/create/upload`, `components/upload/UploadStudio.tsx`, `app/api/upload/**`, `lib/upload/**`, private assets/design revisions, accepted-design handoff to `/new?uploadDesign=…`, verified UID ownership, grants and retention/cleanup behavior. Integrate the library with those records and permission checks. Do not duplicate upload, image processing, storage, acceptance, or fulfillment pipelines. The earlier design-spec baseline statement that matching upload routes were not found is stale against this sprint clone.

`lib/draft/**` is browser session storage with a 24-hour expiry and sanitization; private Upload Studio selections are already UID-bound and revalidated on builder handoff. Build account drafts as a distinct server persistence layer, while preserving existing local/guest draft behavior and offering an explicit import/handoff. Never label device-only state as account-saved.

Order data and order-detail capability routes already exist. History must use verified account ownership, not guest bearer links. Detail content must come from immutable order snapshots/events rather than a mutable contact or regenerated image. `lib/note-preview.ts` and the shared `NoteInteriorPreview` from SPRINT-0023 are prior art for readable inside previews. Existing order state, Stripe state, fulfillment state, and provider logs are different evidence; don't collapse them into “sent.”

Recent sprint indexes: SPRINT-0021 refined checkout/envelope and explicitly preserves the distinction between payment and fulfillment evidence; SPRINT-0022 established private invited Studio and UID-safe accepted design handoff; SPRINT-0023 added signed-in builder menu, private draft transition handling and shared note rendering. Reuse these; extend, do not regress. No semantic index/chapter is selected. No deployment or infrastructure evidence should be inferred from repository files.

## User journeys and product contract

### Navigation and overview

Add `/account` as the account overview and route-backed destinations `/account/history`, `/account/history/[orderId]`, `/account/images`, `/account/images/[assetId]`, `/account/people`, `/account/people/[contactId]`, `/account/dates`, `/account/drafts`, and `/account/settings`. Reuse shared account shell: desktop sidebar near 200px, mobile labeled “Account pages” disclosure with a vertical list. Preserve direct deep links, refresh, browser Back and filter state. Signed-out access routes to sign-in with safe internal return URL; account switch clears prior records immediately; expired auth retains an unsaved local form and prompts re-authentication.

Overview follows the mockup's personal collection style: “A little thought goes a long way.”, next three dates, one resumable draft, up to three recent accepted cards, and “Send a card.” No KPI/reward dashboard and no fixture records. For a saved occasion, hand off contact and occasion IDs into a new draft. Show “Card ordered” only when an order is explicitly linked to that event occurrence, never by recipient-name similarity. First-use state offers add person/send first card. Errors and empty states are distinct.

Main signed-in menu includes **Send a card**, **Account**, **Address book**, **Help**, **Sign out**. Signed-out menu retains sign in/send card. Preserve Studio entry only when current verified grant permits it. Address book opens `/account/people`. Guest sending remains available.

### History and immutable review

`/account/history` supports All / In progress / Mailed / Needs attention, recipient search, server cursor paging (20), actual status-derived counts only. List paid/accepted orders, not unpaid intents. `/account/history/[orderId]` is read-only and owner-checked; show Front / Inside / Envelope tabs, exact saved words/style, accessible plain-text note, order-time address snapshot, total/currency, discount/refund state, available receipt link, order reference and available trusted status events. Missing legacy image or timestamp does not hide other evidence; say “Not available for this older card.” Label Envelope “Address details” if no verified rendering exists. All previews are representations, not photos of mailed goods.

Map states from recorded evidence: payment received/queued = “Order received” or “Preparing”; address deferred = “Address needed” with existing secure completion flow; dispatch states = “Preparing your card”; uncertain provider result = “We’re checking your order” and suppress duplicate send/checkout; MAILED = “Mailed” only with recorded time; failures = “Needs attention” with a safe next step and payment state. Never infer delivered. Preserve accepted order, paid state and history even when fulfillment fails.

“Make a similar card” creates a new editable durable draft with chosen front and proposed words/style, then asks keep/change recipient. Revalidate the current contact/address. Strip old send date, payment IDs/secrets, quote/discount/acceptance flags and guest order tokens. If another draft exists, offer keep or separate. It never charges or submits. Help is available from detail.

### Saved images, generation save, uploads and reuse

Library has Card fronts and Uploads tabs; detail routes display title, provenance date, 17:22 preview for fronts, original aspect containment for sources, and source/front distinction. Card fronts expose Use this front, Rename, Remove from library; prompt is secondary disclosure. Reuse pins the saved immutable rendition/version and performs no generation request. “Make a variation” starts explicit generation and shows allowance first.

Add an optional **Save to my images** action to the mounted generation result path (`app/api/generate-cover/route.ts` caller in `components/v3/CustomAiCommissionDrawer.tsx` and/or builder result surface as confirmed by route inspection). Save only a server-authorized result ID/provenance, never client-submitted arbitrary external URL. Repeat save is idempotent. UI reports saved only after object and metadata commit; failure retains result and offers retry. Signed-out sender may sign in and return to current result, or continue guest checkout. No implicit saving. Existing order snapshot remains independent of library deletion.

Uploads use the existing invited Studio and capability grant, one current source at a time, current JPEG/PNG/WebP, 15 MB policy, server decoding/pixel bounds/orientation normalization/metadata stripping and private source retention. The library must reflect actual upload retention; intentional **Save for later** is the only action that can extend source retention, and must display the policy. A source opens the existing Studio composition flow (not direct printing) and a composed accepted front returns via the existing authenticated `uploadDesign` handoff. Revalidate UID, grant, design revision/hash and acceptance immediately before using it; preview and accepted/master bytes must be identical. Revoked/missing access displays a recoverable explanation and never falls back to a public URL. Deletion/dependency behavior is explicit; do not erase an order snapshot.

### People and multiple dates

`/account/people` supports search/add/import; detail includes display and mailing name, relationship, optional postal address, private note, multiple occasions and related accepted cards. Contacts can exist without a postal address; validate postal fields only when entering checkout. Existing imports become idempotent contact upserts with duplicate review and per-row success/error reporting; don't start reminders as a side effect.

Each contact may own many occasion records: title/type, month/day, optional year or one-off date, recurrence, explicit Feb 29 policy, version and reminder preference. Calendar validation rejects impossible dates and invalid year combinations. New reminder is off by default. Saving/editing a date and pausing/deleting/re-enabling reminder updates contact/date/outbox state transactionally. Existing embedded occasion migration preserves data; uncertain historical opt-in is treated as off pending user choice. Existing checkbox defaults and old “remindMe” fields are not proof of intentional consent.

Builder picker loads contacts and dates in bounded requests; selecting an incomplete contact fills available fields and asks for missing postal details without blocking note writing. User can update the saved contact explicitly or use an order-only address. Occasion association is stored as a reference and frozen on order only after accepted payment. A contact edit never rewrites a paid order.

### Reminders: full local implementation, externally gated activation

“Email me 14 days before” is an explicit per-occasion choice, initially off. Use account timezone, default 9 a.m. local send time; timezone must be validated. An account-wide pause and individual pause/stop controls apply to optional occasion reminders only, not order updates. Settings has verified destination status, time zone, account pause and link to date controls. Pending sends must be invalidated quickly after opt-out, edit, delete or global pause.

Implement durable occurrence/outbox, not a query-and-send cron loop. Unique key is owner + occasion + occurrence date + channel; edits that revert to a prior occurrence cannot double-send. Claim/send transitions use transactions/leases and retry classification; a provider-accepted status means “Sent,” never inbox delivery. Handle idempotency, overlapping workers, stale event versions, cancellation races, provider timeout/unknown result, pause, recipient verification and unsubscribe. Missed run: catch up once only if within 48 hours and occurrence still future; older jobs are marked missed and visible. Explicitly linked accepted card suppresses its pending reminder; cancellation/failure restores eligibility only before due policy. Never infer linkage from a matching name.

Build fake-clock and fake-mail transport tests plus runbook/activation checklist. Unsubscribe uses opaque signed link, GET is read-only for scanners, POST applies opt-out without login; only reminder email is stopped. No email can dispatch in local tests. Mark UI “Not active yet” or equivalent until the scheduler, transactional sender, domain, secrets, monitoring and test inbox are confirmed outside this sprint.

### Durable drafts and Settings

`/account/drafts` list supports resume, rename, duplicate, delete; states distinguish Saving, Saved, retryable save error and device-only. Save across devices using versioned records with optimistic concurrency, retained form values on failures and conflict reload/copy recovery. Sign-in offers deliberate import of the active guest/session draft; never overwrite automatically. Overview's Continue is account-backed only after persisted acknowledgment; otherwise label “Continue on this device.” Suggested inactivity retention is 90 days, but final retention policy is a release decision; do not silently represent it as approved until confirmed. Display policy before saving and expiry.

Settings supports name/sign-in method, validated default personal return address, verified reminder destination, time zone, optional reminder pause, data export request, deletion request, sign out. Keep optional reminders separate from order notifications. Explain actual retention/deletion behavior before confirmation. Do not invent password or stored-payment controls.

## Shared data/API contracts (agree before execution lanes)

Use per-owner Firestore subcollections/collections and transactions; never whole-account-array replacement for new features. Ownership is always derived from verified Firebase bearer token (`uid` in body/query is ignored/rejected). Private responses are `no-store`; validate same-origin for mutations where cookie/origin risk applies; structured errors include stable code, field errors and retryability. Bound every list query, cursor-pagination and server filter. All writes carry `expectedVersion`; conflict returns current version plus safe reload path. Create/save uses client idempotency key and server-generated entity ID. Soft-delete contacts/assets if linked records require stable references; deletion effects are named before confirmation.

Proposed canonical records:

- **Preferences**: uid, displayName, returnAddress, verified reminder destination reference, IANA timezone, global reminder pause, version/timestamps.
- **Contact**: id, ownerUid, display/mailing name, relationship, optional validated address, private note, version/deletedAt.
- **Occasion**: id, owner/contact IDs, type/title, month/day/year/oneOff, recurrence, leap-day policy, reminder opt-in, leadDays=14, consent timestamp/source, version.
- **ReminderOccurrence/Outbox**: stable owner+occasion+date+channel key, event version, dueAt, due-local date, state/lease/attempts/provider ID/acceptedAt/error class; no PII in job payload beyond record references.
- **ImageAsset/AssetVersion**: owner, kind generated_front/uploaded_source/upload_front, source relation, private durable object keys, immutable rendition version/hash/dimensions, title, prompt metadata private, capability requirements, retention/saved/deleted timestamps.
- **Draft**: owner, id/version, asset version, note/style, contact/occasion IDs, address snapshots, progress, updatedAt/expiresAt. No payment secrets, card data, order capability tokens.
- **Order view**: existing immutable order, frozen artwork/note/style/addresses and trusted payment/fulfillment events; optional explicit occasion occurrence ID. Do not copy mutable contact fields into historical render.

Proposed authenticated route families: `/api/account/history` (+ `[orderId]`), `/people` (+ `[id]`), `/occasions` (+ `[id]`), `/images` (+ `[id]` and generated result save intent), `/drafts` (+ `[id]`), `/preferences`, `/reminder-occurrences`/`unsubscribe`. Exact filesystem organization can vary if contracts stay stable. Existing `/api/account` is migration/bootstrap compatibility only; remove legacy write path from the new UI after a guarded migration and prevent old full-array writes from clobbering new contacts. Keep current `/api/upload/**` as upload authority; add library metadata links around it.

Migration is repeatable and observable. Map each legacy `savedAddresses` item to stable contact ID; map its one embedded occasion to stable occasion ID; preserve return address. Import legacy reminders only on deterministic owner/contact/date match; ambiguous duplicates remain paused for account review. Old default-true/remindMe state without explicit consent maps off. Treat `savedCovers` only as candidate URLs; import only when owner, provenance and durable object availability are verified. Preserve historical order snapshots. Store migration version/counts and per-record status; staged read cutover and rollback preserve old data. Once new writes begin, retire old full-array writers or bridge them with version guards before enabling both.

Generation save may accept only an existing server generation result ID. Asset upload intent validates grant/quota and short-lived scoped capability; finalization decodes media, normalizes orientation, strips metadata and records immutable hashes. Reuse acceptance and checkout validate owned asset/version and resolve the same rendition for preview and order snapshot.

**Lane 3 — account shell, history, settings (full stack):** Own `app/account/layout.tsx`, `components/account/**`, history and settings pages under `/account/history/**` and `/account/settings/**`; `lib/account/history/**` and `lib/account/preferences/**`; `/api/account/history/**` and `/api/account/preferences/**`. ## Validation plan

Use unit/service tests with fake auth identities, seeded synthetic orders/assets/contacts, in-memory or emulator Firestore transactions, injectable clock, fake object store and fake mail provider. Cover unauthenticated, unverified, cross-owner, revoked grant, stale version, idempotent retry, schema-invalid input, pagination cursor tampering, missing legacy fields, conflict and provider error. Calendar tests include leap day policies, one-off vs recurring, local 9 a.m. across DST, 14-day boundary, year end, duplicate scheduler invocation, outage cutoff, changed/reverted date.

Verify no private prompt, note, address, date, image or full email is sent to analytics/logs.
