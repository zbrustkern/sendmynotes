# Luna A critique of Sprint 0025 draft B

The draft follows the approved W0–W9 scope and maps all 19 findings. Its strongest choices are the explicit lane handoffs, safe Studio return behavior, non-proxy history design, and the separate rollout/reminder gates. These focused revisions would make execution safer and acceptance less ambiguous:

| Priority | Draft section | Actionable gap | Suggested revision |
| --- | --- | --- | --- |
| P1 | Execution lanes / W6 | `firestore.indexes.json` is assigned to Lane 3, while W6 says the coordinator owns final index reconciliation/deployment. This can create concurrent edits to a release-critical file. | Make Lane 3 publish a proposed index diff/query inventory; assign the sole final manifest edit and deployment to the coordinator, or explicitly transfer ownership at a named point after W0. |
| P1 | Lane 2 / W4 | Lane 2 owns all account pages and Studio; Lane 1 owns account auth/verification UI and W3’s import modal/adapter. These boundaries leave shared pages and import-facing UI ambiguous, especially `app/account/people/page.tsx` and `components/ContactImportModal.tsx`. The latter path is currently `components/ContactImportModal.tsx`, not `components/account/ContactImportModal.tsx`. | Name the import modal and people page owner; define Lane 1’s import API/request shape and Lane 2’s page adapter boundary. Correct the file path and assign one owner for each shared page. |
| P1 | W2 | “One trusted resolver” is a sound requirement, but its shared API and owner are not frozen. Lane 1 lists `lib/account/images.ts` as only a coordinated seam, leaving history, media, and make-similar callers vulnerable to separate implementations. | Specify one exported server-side resolver contract (actor + order ID → trusted front descriptor/bytes or typed unavailable result), its sole owner, and the exact caller handoff to media and make-similar. Require owner/grant validation inside that boundary. |
| P1 | W6–W7 | Production configuration facts are left generic. The approved plan corrects the audit: `UPLOAD_PRIVATE_BUCKET` is a plain value; only verified project secret IDs should be treated as secrets; all scheduler jobs need authenticated POST calls; reminder delivery must remain explicitly false. | Name the verified config-versus-secret distinction, require a target-project preflight before any provisioning, explicitly pin `ACCOUNT_REMINDER_DELIVERY_ACTIVE=false`, and test each job’s wrong-token rejection. Do not infer or copy staging credentials. |
| P1 | W9 / Definition of done | Rollback mentions preserving new records, but lacks a concrete proof that the deployed rollback path can read account writes or safely disable legacy array writers. The plan makes this a specific release risk. | Add a staging rollback rehearsal with new per-record people/date/draft/image fixtures, compatibility/read-only fallback evidence, and proof that legacy array writes are disabled without deleting new records or objects. |
| P2 | Canonical guardrails | The draft preserves product direction and correctly says Apple Pay is unverified, but omits the canonical conversion baseline and founder-test qualification. | State that there are zero independent customer conversions and the one paid order was the founder test; avoid reporting this sprint’s staging evidence as customer validation. |
| P2 | W1 / W9 | W1’s acceptance is useful but does not explicitly test same-UID Firebase user reload/token refresh and rejection of malicious return destinations. Those are the core correctness/security edges of the proposed verification path. | Add same-UID refresh plus server-side gated-action recheck, arbitrary/cross-origin return rejection, and controlled-inbox verification to the W1 staging matrix. |
| P2 | W7 | The draft covers uncertain delivery and monitoring, but the activation criteria could distinguish provider acceptance from actual inbox receipt and include no-backlog behavior as an observable gate. | Keep delivery off until a controlled opted-in inbox confirms receipt, correct link, unsubscribe, and that activation cannot send expired backlog; record this separately from mocked transport tests. |

No scope-level omission was found: C1–C5, U1–U6, A1–A4 and W0–W9 are represented. These are clarifications to ownership and evidence, not requests to defer a required feature.
