# Sprint 0025 Luna B critique of Luna A draft

Luna A’s draft is strong and closely tracks the approved W0–W9 plan. It maps all 19 findings, separates production rollout from reminder activation, preserves the no-fulfillment/no-customer-email boundary, specifies fake-provider tests, and gives useful acceptance cases for verification, historical art, import consent, draft continuation, Studio and privacy operations. Keep its finding matrix and most work-package structure.

Before synthesis, make these implementable corrections:

1. **Resolve file ownership collisions.** Lane 1 claims `components/account/**` and `app/account/**`; Lane 3 owns privacy admin UI, while Coordinator owns `context/AuthContext.tsx`, builder and payment paths. Name explicit exclusions: reserve privacy-admin UI/API to Lane 3; reserve shared account shell/auth context and `app/preview/entry/client.tsx` to Coordinator; Lane 1 owns only verification modal-specific UI and named history/import/account routes. For W6, have Lane 3 deliver a reviewed resource manifest and additive index diff; Coordinator owns final `apphosting.yaml`, `firestore.indexes.json`, merge and deployment so no two owners edit the same release files.

2. **Specify Studio source/version lifetime and cancellation semantics.** The “three successful versions for the active owner/source session” phrase needs a concrete backing record, identity key, expiry/cleanup policy, and storage boundary. Define what survives refresh, sign-out, grant expiry, and source deletion; retain current accepted/ordered master independently and evict only old unselected temporary versions. The edit handoff must carry validated source/generation/design IDs plus prompt, lettering, treatment and selected version—not private URLs. If editable source has expired, offer saved-source re-entry only when verified available; a flattened front is reusable but never editable. Back/cancel must leave current artwork and draft intact; invalidate acceptance and quote/payment only after a changed front is actually selected.

3. **Close the operations evidence loop.** W6/W7 acceptance should record the target project, exact live resource/index states and evidence source; distinguish “API query unavailable/not verified” from “resource absent.” Include dry-run/report mode or disposable-fixture proof before cleanup touches real rows, prove bounded cleanup progresses past tombstones, and explicitly state valid unused saved library images and ordered masters are never cleanup candidates. Capture authenticated job run summaries and alert delivery/retry without exposing bearer tokens or customer content.

4. **Make deployment ownership and gates sequential.** W6 says indexes/deployments are prepared while W9 later verifies staging. State the order: complete W0 and final query/config inventory, provision isolated staging resources, deploy additive indexes and verify READY, deploy the exact integrated candidate, then run signed-in acceptance. Production resource provisioning/preflight evidence is a distinct release packet item; production application rollout is only after founder authorization. Reminder activation remains a later independent approval and controlled inbox proof.

5. **Complete post-release and rollback proof.** The draft says what to preserve during rollback but should require a rehearsed compatibility bridge/read-only fallback for newly written account records and an explicit rule for disabling old array writers. Add the post-authorization production smoke sequence—health, real sign-in, safe private-storage read/write/delete fixtures, cross-UID denial, account queries/indexes and operator monitoring—before increasing access. Do not call production ready from the staging candidate alone.

6. **Tighten a few acceptance details.** W2 should test legacy object redirect rejection and MIME/size/time limits, plus demonstrate one shared resolver produces the same bytes for detail/media/reuse. W4 should explicitly test private object-URL revocation on UID changes and failed thumbnail loads. W7 should test no overdue backlog is dispatched on activation and GET unsubscribe links do not mutate consent. W9 should mark Apple Pay unverified unless actually exercised on device; A already notes this, so keep it explicit in the final release report.

These changes preserve Luna A’s good structure while removing ownership ambiguity and turning resource, Studio-lifetime, staging and rollback requirements into evidence reviewers can verify.
