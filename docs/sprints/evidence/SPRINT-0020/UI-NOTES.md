# SPRINT-0020 UI implementation notes

- Updated `components/flow/EnvelopePreview.tsx` to use the blank paper and domestic postage artwork as decorative images behind live DOM address text. The 5:3 optical frame is a design choice, not a supplier envelope measurement. Paper uses `object-cover`; if content expands vertically, its surface texture crops while the CSS envelope edge and shadow remain responsive.
- Address blocks retain the sender and recipient values as selectable text, wrap long unbroken input, keep apartment lines separate, and include generic examples only for empty fields. Deferred recipients show their name and “Street address to be added later.” A supplied catalog country name takes precedence over the country code.
- Both artwork images have an `onError` transition. The paper surface remains white when its texture fails; postage falls back to neutral CSS. International preview uses neutral CSS postage and does not assert a particular mailing service.
- Normal text sizing is calibrated for the bundled Handwrytten font glyphs: sender 20 CSS px and recipient 27 CSS px with normal weight. The browser fixture can compare the five supported styles and failure cases.
- Parent integration removes the preview card/badge chrome, adds the small “Your envelope” label and the restrained return-address sentence, and passes the matching mailing catalog display name.
- Reviewed the final raster assets at full resolution: blank paper texture (1200×720, 16,884 bytes) and domestic postage (300×375, 31,190 bytes), 48,074 bytes combined. They contain no address, barcode, denomination, date, or cancellation mark.
- Checks passed: `node --import tsx tests/envelope-preview.test.tsx` (13 cases), `node --import tsx tests/international-addressing-ui.test.tsx`, `node --import tsx tests/sprint-0019-ux.test.ts` (28 cases), `npx tsc --noEmit`, and the isolated fixture build.
- An isolated interactive browser fixture and local failure-state server are documented at [fixture/README.md](fixture/README.md). Browser/device visual review has not been claimed here. Static render checks cannot simulate an actual browser image-error event or verify Safari text sizing/zoom behavior.
