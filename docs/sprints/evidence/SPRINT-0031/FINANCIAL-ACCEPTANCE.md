# Hosted financial acceptance

Run `node docs/sprints/evidence/SPRINT-0031/hosted-finance.mjs --staging-test` from this checkout after the staging purchase flag is enabled. It uses the project's five-file fixture set's 100-household CSV, two private synthetic projects, the staging public Stripe key and `pm_card_visa`. The report contains counts and USD cents. The mode-0600 state file in `/private/tmp` allows the same test purchases to resume after interruption.

For the H099 refund, supply an authenticated staging admin cookie file using `WEDDING_ADMIN_COOKIE_FILE`, or add `--staging-iam-refund` to that command. Both paths call the application’s `refundWeddingCard` service. A repeat uses the same operation key. The IAM option runs only in the local acceptance process, using the operator’s own active Google account. It verifies permissions to read the staging runtime and its bound Stripe secret and to transact on staging Firestore. The secret and Google access token stay in process memory. The Firestore client uses that same Google identity. No application admin session is issued.

Before the IAM operation, the runner requires one serving staging revision with held fulfillment, test-only Stripe, and the correct project. It checks a run-specific import marker, a synthetic project younger than 24 hours, both already-settled batches, 100 paid ordinals, H099’s frozen French address, the $12 allocation and the actual $18.50 test charge. Another cohort or an unrelated refund fails closed. The only permitted mutation is the one full H099 refund and its normal application records. The application records a pseudonymous operator ID. Replay verifies the provider amount, the $730 combined net and the tracker’s refunded status.

Schedule `/api/cron/wedding-reconcile` every minute on staging. Each pass visits at most four overdue batches and materializes at most 20 cards per visited batch. The final mixed batch has two cards. The runner confirms those two at Stripe and then uses read-only status polls every 20 seconds, for up to 18 minutes. The held rows must appear without a browser write. The IAM path separately checks the ordinary signed Stripe webhook inbox and reports `observed` or `pending`. If webhook delivery is delayed, rerun the same acceptance state to check again. Neither the test runner nor the local operator invokes a supplier or fabricates a provider event.
